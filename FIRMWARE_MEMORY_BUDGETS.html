Set Flash and RAM budgets that catch growth

A firmware image can fit the linker layout while growing more than your team intended. A total budget limits the current build. A growth budget limits its increase from the baseline. FW Mem Guard evaluates both for Flash and RAM.

Keep three numbers separate

  • Linker region capacity: the size declared in the selected memory region.
  • Total budget: your permitted current usage, which may intentionally leave headroom.
  • Growth budget: your permitted increase over the baseline. Zero means no positive growth; it does not disable the check.

Allocated section bytes are measured. This is not a measurement of peak runtime heap or stack use. Initialized data occupies RAM while running and also needs its load image in Flash; counting those bytes in both totals is intentional. Reserved address span and allocated byte totals are different quantities.

Reproduce a one-byte boundary failure

Download and set up the verified MicroPython v1.24.1 example. Keep all four original MAP/ELF files unchanged. Select FLASH (not FLASH_TEXT) and RAM.

Example limits in bytes; these are not universal project defaults.
CheckLimitActual
Flash total524288300452
Flash growth82408240
RAM total11468826536
RAM growth40964096
  1. Validate and save the project with these limits. Expect PASS.
  2. Run FW Mem Guard: Edit Budgets. Lower only RAM growth from 4096 to 4095. Leave the other three budgets unchanged.
  3. Choose Validate and Save. It automatically compares the builds. Expect one RAM-growth violation: actual=4096, limit=4095, engine exit code 2.
  4. Restore RAM growth to 4096 and validate/save again. Expect PASS.

This changes a budget by one byte, not the firmware. Equality with a limit passes; exceeding it fails. Inspect the raw failing engine output and restored result.

Review a failure before changing its limit

Confirm the intended baseline, completed current build and effective limits. If the growth was expected, review the tradeoff before approving a new budget. If it was unexpected, use the build's MAP/ELF and toolchain to investigate. The published version does not attribute changes to objects or libraries.

Export Report for Sharing opens reduced JSON in an unsaved editor tab. Review it before saving or sharing. It omits paths, section names and symbols, but totals and budgets may still be sensitive.
